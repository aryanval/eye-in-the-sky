# EITS-GCP-002: Public principal added to bucket object-access policy

This single-event design requires `protoPayload.serviceName=storage.googleapis.com`, `methodName=storage.setIamPermissions`, successful outcome, `resource.type=gcs_bucket`, a known log-owning project, and `protoPayload.serviceData` typed as `type.googleapis.com/google.iam.v1.logging.AuditData`. One element of `policyDelta.bindingDeltas` must contain **all three** predicates: `action=ADD`, `member` equal to `allUsers` or `allAuthenticatedUsers`, and `role` equal to `roles/storage.objectViewer`, `roles/storage.objectAdmin`, or `roles/storage.admin`. The bucket's `protoPayload.resourceName` must be present. Matching multiple deltas retains one finding with all predicate rows and one supporting event UID.

Public fields and interpretation: [Google's audit format and Cloud Storage serviceData mapping](https://docs.cloud.google.com/logging/docs/audit/understanding-audit-logs), [Google IAM AuditData schema](https://github.com/googleapis/googleapis/blob/master/google/iam/v1/logging/audit_data.proto), [PolicyDelta/BindingDelta schema](https://github.com/googleapis/googleapis/blob/master/google/iam/v1/policy.proto), [Cloud Storage auditing](https://docs.cloud.google.com/storage/docs/audit-logging), and [Google's documented detection example](https://cloud.google.com/blog/products/identity-security/announcing-cloud-analytics-googles-latest-partnership-with-mitre). Only the serviceData representation is supported by this rule; arbitrary metadata shapes are not assumed equivalent.

Public principals can broaden object access beyond the intended audience. Publishing an authorized website, open dataset, or release artifact produces an identical grant, so these are intentional evaluation false positives. `allAuthenticatedUsers` is broad authenticated access, not anonymous access. [Public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention) and other controls can limit effective access. The record does not establish object sensitivity, actual reads, exfiltration, malicious intent, authorization or the duration of exposure. A policy delta is more informative than merely finding a public member in a complete returned policy.

Observed facts are the successful policy-setting record and exact matching delta, resource and scope. Inference: investigate a potential unauthorized broad-access grant. ATT&CK T1098.003 maps the additional cloud-permission hypothesis; its applicability depends on the investigation. [SQL](../../src/eits/sql/EITS-GCP-002.sql) is executable and [metadata](../../src/eits/rules/gcp.json) lists required fields and limitations.

Success requires explicit numeric zero or an explicitly empty status object; omitted/null status is unknown. ACLs, custom roles, other bucket roles and newer/alternate delta representations are outside this rule. Missing serviceData or bucket identity is not reconstructed from a request. There is no severity upgrade based on a bucket name, IP or actor email. Tuning requires object classification, publication authorization, bucket-policy history and constraints. No blanket public-content suppression ships. The synthetic corpus contains malicious and legitimate grants, ambiguity, missing deltas, unknown status, wrong delta tuple, removals and denied requests; [separate labels](../../evaluation/gcp-ground-truth.json) measure the resulting FP/FN.
