# HUNT-003: New service-account keys and observed use

Hypothesis: unexpected service-account key creation and subsequent use can reveal persistent access or automation that deserves review, including activity outside an alert's 30-minute/API boundary. [SQL](../../src/eits/sql/HUNT-003.sql) inventories successful **and unknown-outcome** key-creation records, with any subsequent exact key-attributed API activity in the same log-owning scope over a configurable window (default 24 hours; greater than zero and at most 744 hours).

Required telemetry is GCP `protoPayload` AuditLog creation records plus optional subsequent `authenticationInfo.serviceAccountKeyName`. The creation's `response.name` is converted to a full resource name only by adding `//iam.googleapis.com/`. No account/email aliases or cross-cloud identities are inferred. Missing key response, timestamp or scope is retained as `unresolvable`; otherwise zero matching calls is `no_use_observed`. Neither means the key was unused. Unknown-outcome creation is explicitly labeled and does not prove a key was issued. Denied creation is excluded.

Each lead includes the exact creation UID, use UIDs, first/last observed use, action/service counts and failures. A key used after 30 minutes for non-policy APIs still appears; no alert threshold is applied. Counts describe the supplied corpus and window, not complete cloud activity. The [source notes](../sources/gcp.md) explain incomplete response and key-attribution coverage.

Suspicion increases with unapproved key creation, a new service/API footprint, unexpected privileged operations or repeated access failures. Suspicion decreases with documented rotation, a deployment owner explaining the key's lifetime and workload, and matching authorized changes. Neither a high count nor a new IP establishes compromise. Before calling activity malicious, obtain change authorization, service-account/key ownership and lifecycle records, relevant policy snapshots, complete audit coverage and independent evidence of unauthorized use. These are investigative evidence requirements, not dependencies of this offline project.

Every lead is exploratory. It has no severity, alert ID, TP/FP verdict or implied maliciousness. The synthetic corpus and tests verify used, unused, unknown, missing-attribution and window behavior, with exact retained evidence resolution.
