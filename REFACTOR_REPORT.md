# Architecture refactor milestone

The shared ingestion, finding and evaluation architecture now supports distinct
source adapters and arbitrary nonempty evidence sets. AWS CloudTrail remains the
only implemented vendor parser. This milestone adds no Azure/Entra/GCP parser,
security detection, hunt, live-account dependency or deployment infrastructure.

This is the historical refactor report for commit `4a44570`. The subsequent
provider implementations are documented in [PHASE2_REPORT.md](PHASE2_REPORT.md).

## Exact compatibility effects

- **AWS identities are unchanged.** The legacy raw-JSON event UID, ordered
  finding UID inputs, rule versions and authored SQL hashes remain stable.
  Other source domains use a disjoint `evt_v2_` namespace that incorporates
  provider, source, typed scope, tenant and raw JSON.
- **Database schema becomes version 2.** Opening a version-1 database adds
  nullable `scope_type`, `scope_id`, `tenant_id` and fills AWS scope from the
  existing account field. Existing event columns, UIDs, raw bytes and source
  references survive unchanged. Migration is transactional; no downgrade is
  provided, and the original executable rejects a migrated version-2 database.
- **Normalized/evidence output adds scope fields.** `account_id` remains an AWS
  compatibility field. Context timelines now include provider/source/typed scope
  and derive bounds from all supporting events; unknown scopes do not expand
  context. Context inclusion does not establish causality or shared identity.
- **Manifest validation is stricter.** Invalid SHA-256 declarations, duplicate
  file entries, unsupported formats and invalid collection-scope metadata fail
  before import. Every evidence reference must agree with its manifest's explicit
  collection scope, including identical raw records collected in different tenants.
- **Queries execute within their registered source.** A generic SQL wrapper
  prevents other sources from affecting joins, exclusions or hunt counts. The
  authored query files are unchanged; their original `sql_sha256` values remain
  in findings. Executed wrapper hashes and source parameters are recorded separately.
- **Evaluation output is version 2.** New reports record schema version, all
  executable/resource hashes, resolved registry hash and execution scope. They
  intentionally have new runtime fingerprints while preserving AWS outcomes.
  UID anchors support any nonempty expected evidence set. Legacy source-ID
  anchors are rejected when those IDs are ambiguous across stored events.
- **CLI remains compatible with the AWS walkthrough.** Existing commands and
  revision names work. `status` adds schema/source information; `hunt --hunt-id`
  selects a registry entry. Reserved provider sources fail explicitly rather
  than accepting unsupported telemetry.

The baseline remains the default. Rule 001 still has TP/FP/FN = **2/1/4**;
rule 002 baseline remains **3/2/3**, and restart-aware remains **2/1/4**.
Ambiguous cases remain excluded from precision/recall. These are fixture-specific
measurements, not production performance estimates.
